# sheets — 공용 스프레드시트 구조

> 코드가 이 구조(탭 이름 + 컬럼 위치)를 그대로 기대한다. **탭 이름 변경/컬럼 삽입 금지.**
> 열을 추가하고 싶으면 반드시 **기존 열 오른쪽 끝에** 추가할 것.

## 탭 목록

| 탭 이름 | 누가 쓰나 | 용도 |
|---|---|---|
| `부족원` | 사람이 관리 | 명단 · 독립(퇴사) 여부 · PIN |
| `정기공격일자` | (레거시, 앱 미사용) | 과거 월별 정기모임 투표 기록. 지금은 `raid_overrides` 스크립트 속성 사용 |
| `자연재해` | 앱이 관리 | 번개 모임 |
| `벽화` | 앱이 자동 기록 | 사진/영상 인증 로그 |
| `명예의전당` | 앱이 자동 기록 | 월별 영상 출품/투표 |
| `공지` | 앱이 자동 생성/관리 | 공지사항 |
| `인증현황` | 정산 실행 시 자동 갱신(누적) | 월별 정산 결과 — 열=월 |
| `완료기록` | 앱이 자동 생성/기록 | 정기공격/자연재해 완료 처리 로그 |
| `레벨완등` | (레거시, 앱 미사용) | 랭킹 기능 제거 전 레벨(난이도)별 완등 횟수 기록. 과거 기록 보존용 |
| `오류로그` | 앱이 자동 생성/기록 | 예기치 못한 백엔드 오류(시각·action·메시지). 헤더+최근 300행 유지, 흔한 사용자 오류는 제외 |
| `예산` | 앱이 자동 생성/기록 | 부족 예산 — 정산 적립(자동)·사용 이력(담당자 등록) |
| `오픈세션` | 앱이 자동 생성/기록 | 정기 오픈 세션(날짜+장소) — 개설/수정/삭제 |

## 부족원 — 사람이 직접 관리 (A열만 직접, 나머지는 앱)

> 명단(A열)은 시트에서 직접 편집해도 되고, **웹 관리 탭(관리자) → 👥 부족원 관리**에서 추가/이름수정/삭제해도 된다
> (`addMember`/`renameMember`/`deleteMember`). 이름을 바꾸거나 삭제해도 **과거 기록은 이전 이름으로 남는다**(이름이 여러 시트의 키라 일괄 치환 안 함). 관리자 이름은 앱에서 수정/삭제 불가(권한이 이름 기준이라) — 시트/속성에서 직접.

| 열 | 내용 | 비고 |
|---|---|---|
| A | 이름 | **필수.** 앱의 모든 기능이 이 이름 기준 |
| B~H | (자유) | 코드가 사용하지 않음 — 연락처·독립일 메모 등 자유롭게 |
| I | PIN | **앱이 자동 기록. 손대지 말 것.** 분실 시 관리자 페이지에서 초기화 |
| J | 지원여부 | `FALSE` = 정산(지원) 제외, 빈칸/`TRUE` = 지원 대상. **웹 관리자 페이지에서 설정** (직접 편집 불필요) |
| K | 휴면종료일 | `yyyy-MM-dd`. 그 날짜까지 **휴면** — 정산 대상에서 빠지고 인증현황에 `휴면` 표시. **날짜가 지나면 자동 복귀**(해제 불필요). 최대 3개월. **웹 관리자 페이지에서 설정** |
| L | 직책 | `부족심사중` / `조약돌` / `간석기` / `고인돌` / `팀장`. 빈칸 = `부족심사중`. **웹 관리자 페이지에서 설정**. `팀장`은 기본적으로 정기 오픈 세션 개설 권한 대상(opensessions.gs 참고) |

## 정기공격일자 — ⚠️ 더 이상 앱이 쓰지 않음 (레거시)

정기공격을 후보 투표로 정하던 시절의 시트. 지금은 정기공격이 **고정 일정**(기본값: 그 달 둘째 주 금요일 20시 +
`CONFIG.RAID_LOCATIONS` 위치 로테이션, 관리자가 `setRaidDate`로 override)으로 바뀌면서 이 시트를 더 이상 읽거나 쓰지
않는다(votes.gs `raidEntryFor_`/`getRaidSchedule_` 참고). 과거 투표 기록 보존을 위해 시트 자체는 삭제하지 않았다.
override 값은 Script Property `raid_overrides`에 `{ '2026-07': {date, loc, note, setBy, setAt} }` 형태로 저장된다.

## 자연재해 (번개) — 전부 앱이 관리

| 열 | 내용 |
|---|---|
| A | 날짜 (앱이 기록) |
| B | 위치 (앱이 기록) |
| C~ | 투표자 (첫 명은 등록자) |

- 수정/완료 처리/취소 권한은 **개설자 또는 관리자**. 개설자는 Script Properties `flash_owners`에서 우선 조회하고,
  기록이 없으면(과거 번개 등) **C열 첫 투표자**로 폴백한다(`flashOwnerOf_`, votes.gs). 프론트도 동일한 폴백을 적용한다.

> **위치 열 자동 마이그레이션**: 자연재해 시트의 `위치`(B) 열은 `ensureLocationColumns_`(votes.gs)가 배포 후 첫 접근 시
> **1회 자동 삽입**한다. 1행의 헤더 `위치`가 그 마커다 — **이 헤더 셀을 지우면 다음 접근에서 다시 열을 삽입하므로 건드리지
> 말 것.** 기존 `날짜 @ 위치` 라벨을 날짜(A)/위치(B)로 분리한다. (정기공격일자 시트는 더 이상 앱이 쓰지 않아 대상 아님.)

## 공지 — 앱이 자동 생성 (첫 공지 등록 시)

| A | B | C | D |
|---|---|---|---|
| 등록일시 | 작성자 | 내용 | 고정 |

- D열 `고정`이 truthy(`고정`/`TRUE` 등)면 홈에 항상 노출. **홈은 고정 공지 전부 + 고정 아닌 최신 1건만** 보여준다(`getHomeNotices_`).
- 고정/해제는 웹 관리자(더보기 탭 공지 목록의 `📌 고정`/`고정 해제`). 첫 고정 시 D열 헤더가 없으면 앱이 보강한다.

## 인증현황 — 열=월 누적, 행=이름(오름차순)

정산 실행할 때마다 **해당 월 열만** 다시 계산해서 덮어쓴다. 다른 달 열은 그대로 보존(누적).
활동일자·장소·Drive 링크 같은 상세 정보는 담지 않는다(그건 `벽화` 시트에 이미 있음) — 이 시트는 **월별 O/X 현황만** 빠르게 보기 위한 용도.

| A(이름) | B(2026-06) | C(2026-07) | ... |
|---|---|---|---|
| 김광훈 | O | O | |
| 이희주 | X | 정산 취소 | |
| 정민재 | 지원 제외 | 지원 제외 | |

- 셀 값: `O`(인증 완료) / `X`(미인증) / `지원 제외`(부족원 시트 J열 FALSE) / `정산 취소`(관리 탭에서 그 달만 개별 취소)
- **월 헤더(B1~)는 그 달 정산 폴더로 가는 링크** — 클릭하면 `[정산폴더]/yyyy-MM`로 이동 (`linkStatusHeaders_`). `SETTLE_FOLDER_ID` 미설정 시 링크 없이 텍스트만
- 앱이 전적으로 관리 — 수동 편집 시 다음 정산 실행에서 덮어써질 수 있음

## 완료기록 — 앱이 자동 append (첫 완료 처리 시 시트 생성)

정기공격(고정 일정)/자연재해(번개)를 "완료 처리"할 때마다 한 행씩 쌓인다. 완료 처리된 항목은 일정 목록(UI)에서는 사라지지만
이 시트에는 영구히 남는다 — 활동이 실제로 있었는지 나중에 확인하는 용도.

| A | B | C | D | E | F | G |
|---|---|---|---|---|---|---|
| 처리일시 | 종류(정기공격/자연재해) | 월 | 날짜 | 위치 | 참여인원(쉼표) | 처리자 |

- 정기공격은 그 달 고정 일정을 "완료 처리"(관리자 전용)하면 D열에 실제 날짜가, "모임 없음으로 종료"(`completeRaid`의
  `cancelled` 옵션)하면 D열에 `(모임 없음)`이 기록된다. 완료 시 참여인원(F열)은 그 달 **참석확정(RSVP) 'yes' 명단**을 쓴다.
  완료 여부는 Script Properties `completed_raid_months`로만 관리하고, 이 시트는 기록 전용.
- 자연재해는 등록자 또는 관리자가 완료 처리할 수 있고, `자연재해` 시트의 해당 행은 취소(삭제)와 동일하게 제거된다(전부 앱이 관리하는 시트이므로).
- `getCompletionLog` GET action으로 최신순 조회 가능(더보기 탭 "✅ 완료된 모임"). `needsCertNudge_`(auth.gs의 `session_`)가 이번 달 F열(참여인원)에
  포함된 이름을 이번 달 인증 여부와 대조해 로그인한 본인에게만 인증 리마인드를 띄운다.

## 예산 — 앱이 자동 생성/기록 (정산 담당자·관리자)

| A | B | C | D | E | F |
|---|---|---|---|---|---|
| 일시 | 구분(적립/사용) | 금액 | 내용 | 처리자 | 월 |

- **적립**: 정산 실행(`runSettle`) 시 자동 1행 — 금액 = **정산된(인증 완료) 인원 × 인당 적립액**(기본 5,000원, 스크립트 속성 `budget_per_person`).
  F열(월)이 중복 방지 키 — 같은 달을 다시 정산하면 그 행을 **갱신**한다(중복 적립 없음).
- **사용**: 담당자가 앱(관리 탭 💰 부족 예산)에서 등록/삭제. 잔액 = 적립 합계 − 사용 합계.
- 조회·기록 모두 **정산 담당자 또는 관리자만**(`canSettle_`).

## 오픈세션 — 앱이 자동 생성/기록 (첫 개설 시)

정기 오픈 세션(특정 날짜+장소, 반복 아님). 여러 날짜를 한 번에 등록하면 그 개수만큼 행이 쌓인다.

| A(ID) | B(날짜) | C(장소) | D(설명) | E(개설자) | F(등록일시) |
|---|---|---|---|---|---|
| (uuid) | 2026-09-12 | 더클라임 강남 | 초보 환영 | 이희주 | 2026-09-03 10:00:00 |

- **B열(날짜)은 텍스트로 저장**(`'` 접두사) — 시트가 자동으로 날짜 타입으로 바꾸면 `getDisplayValues()`가
  로캘 형식으로 돌려줘서 `'yyyy-MM-dd'` 파싱이 깨지기 때문(PIN·휴면종료일과 동일한 이유). 직접 수정 시 주의.
- **A열(ID)** 로 행을 찾으므로 행 순서가 바뀌거나 삭제돼도 안전. 수정/삭제는 개설자 또는 관리자만.
- 개설 가능 직책은 Script Property `open_session_roles`(기본 `['팀장']`, 관리 탭에서 설정).

## 레벨완등 — ⚠️ 더 이상 앱이 쓰지 않음 (레거시)

레벨(난이도)별 완등 순위를 보여주던 '랭킹' 탭 기능 전체가 제거되면서 이 시트도 더 이상 앱이 읽거나 쓰지 않는다
(`levels.gs` 및 `getLevelBoard`/`setLevels`/`setLevelRecord`/`setMyLevelRecord` action 삭제). 과거 기록 보존을 위해
시트 자체는 지우지 않았다.
